# superdesign-inspo

Тонкий оркестратор. Inspo даёт доказательства с живых сайтов. Установленный скилл Superdesign владеет локальным `.superdesign/design-system.md`, репликой текущего UI и черновиком на канвасе. Код продукта этот скилл не пишет: на выходе ссылка на черновик и промпт на внедрение. Этот файл установленные скиллы не подменяет и не копирует.

Публичного готового моста нет. Не форкай `superdesigndev/superdesign-skill` и не форкай `Nutlope/inspo`.

Это контракт, не поставка автоматизации. Каталога `scripts/` нет. Не требуй отсутствующий скрипт как блокер.

Установка: `<SKILLS_ROOT>/superdesign-inspo/SKILL.md`.
Указатель: `<VAULT>/60_skills/workspace/superdesign-inspo.md`.

## Когда звать

Пользователь просит дизайн или редизайн UI с опорой на реальные сайты, и в сессии есть Inspo MCP и скилл Superdesign. CLI проверяй в шаге 1 и Fallback; из-за CLI этот скилл не пропускай.

## Когда не звать

- Обычный код и правки без визуального референса.
- `session-distill`.
- Parallel deep research (`save-research`).
- Просьба сразу сверстать продукт.
- Задача только на Superdesign, без живых сайтов: веди установленный скилл `superdesign`.
- Задача только на чтение архива, без черновика: оставайся в Inspo MCP.

## Workflow

1. **Проверка.** Нет Inspo MCP или нет установленного скилла Superdesign — остановись и назови, чего не хватает. CLI Superdesign — это preflight того скилла (`npx --yes @superdesign/cli@latest`), не отдельный глобальный бинарь. Если preflight не стартует, остановись и назови Superdesign. Не имитируй отсутствующий инструмент. См. Fallback.

2. **Задача, коротко.** Зафиксируй: новый экран или существующий, аудитория, обязательные секции, есть ли уже `.superdesign/design-system.md`. Если это уже сказано в запросе, не устраивай опрос. Если в запросе нет нового или существующего экрана, аудитории или обязательных секций — задай один общий вопрос. Не выдумывай их. Для нового экрана не собирай `replica_html_template` и не выдумывай секции состояния «до». Существующий непустой `.superdesign/design-system.md` прочитай и оставь как есть.

3. **Исследование Inspo. Мало референсов.**
   - Сначала один вызов `recommend(brief)`.
   - Из ответа выбери 1–2 экрана. Пять exemplars внутри `recommend` — не повод вызывать `get_screen` на каждый.
   - Для выбранных: `get_screen`. `get_design_system` — только если после `get_screen` всё ещё неясны роли палитры или шрифтовая иерархия.
   - `find_examples_for_macrostructure`, `find_similar` и `find_by_color` — только если остался один конкретный вопрос.
   - `get_reference_jsx` вызывай, только если нужен один композиционный приём. Id возьми из `recommend`; `find_reference_components` — один раз и только если id там нет. Это пример приёма, не код продукта.
   - Подсказка Inspo «3–5 экранов» и цифры Refero (3–5 поисков, 3–4 стиля) этому скиллу не бюджет. Прошлый прогон с тремя ветками — не квота «всегда три сайта». `search_screens`, `compare` и `find_components` не вызывай.

4. **Пакет доказательств** на каждый выбранный экран — шаблон ниже.

5. **Передача в Superdesign.** Прочитай установленный скилл `superdesign` и выполни только этот набор:
   - его preflight и, если preflight просит, `login`;
   - если в репозитории есть фронтенд, а init по правилу того скилла ещё не собран — сначала init (`.superdesign/init/`); это не исходники продукта;
   - локальный `.superdesign/design-system.md` только из продукта пользователя; существующий непустой файл не заменяй;
   - `replica_html_template` только для UI, который уже есть в репозитории;
   - `create-project`, если проекта ещё нет. Для существующего экрана `create-design-draft` — репродукция текущего UI репозитория, без пакета Inspo. Пакет доказательств — бриф вариации только для `iterate-design-draft`. Для нового экрана, где состояния «до» нет, тот же пакет можно передать в `create-design-draft`.
   - в ответ положи canvas и/или preview, которые CLI напечатал.

   Вне этого набора: `WEBSITE.md`, `extract-website` по URL Inspo или страницам архива, `design-with-your-model.md`, запись архивного `DESIGN.md`, вывода `extract-website` или prompt library в `.superdesign/design-system.md`. `DESIGN.md` сайта в архиве и локальный `design-system.md` — разные файлы.

   Сколько веток — решает просьба пользователя и скилл Superdesign. Исходники продукта не меняй.

   Если `create-design-draft` или `iterate-design-draft` не создали черновик, остановись и скажи, что черновик не создан. Ссылку не выдумывай и промпт на внедрение не отдавай.

   Если черновик создан — отдай напечатанные CLI ссылки и промпт на внедрение.

Slug и `<VAULT>` для черновика не нужны. Не создавай `10_projects/<slug>/` и не пиши `decisions.md`. Если просят только запись в vault, а `<VAULT>` неизвестен — остановись и спроси путь.

## Пакет доказательств

На каждый выбранный экран:

- URL или slug
- макроструктура
- роли палитры
- шрифтовая иерархия
- разбор фолдов
- переносим: иерархия, ритм, роли цвета, принципы типографики
- не копируем: имя, логотип, текст, картинки, фирменный декор, чужой JSX целиком

## Промпт на внедрение

Отдай отдельным блоком только после созданного черновика. Заполни пункты из запроса. Если после одного вопроса аудитория, обязательные секции или новый/существующий экран так и не названы, пиши `не сказано`. Не выдумывай. Для нового экрана «Состояние «до»» — `нет`. Следующий ход сверстает UI по нему, без повторного исследования.

```markdown
Экран:
Новый или существующий:
Аудитория:
Обязательные секции:
Состояние «до»:
Переносим: иерархия, ритм, роли цвета, принципы типографики.
Не копировать: имя, логотип, текст, картинки, фирменный декор, чужой JSX.
Источники урока (не бренд продукта): URL или slug.
Черновик: <canvas и/или preview URL, которые CLI напечатал; отсутствующую не выдумывай>
```

## Запреты

- Форк `superdesigndev/superdesign-skill` или `Nutlope/inspo`; своя копия их инструкций вместо установленных скиллов.
- Вызов InspoAI (`inspoai.io`, `inspoai_search_designs`).
- Молча перезаписать существующий `.superdesign/design-system.md` или подменить его заметкой направления.
- Собрать `replica_html_template` со страницы Inspo.
- Вставить чужой JSX, имя, логотип, текст, картинки или фирменный декор в черновик или в продукт.
- Менять исходники продукта.
- Имитировать отсутствующий MCP или CLI, в том числе выдуманным preview URL.
- Требовать каталог `scripts/`.
- `extract-website` по URL доказательств Inspo или страницам архива.
- Записывать архивный `DESIGN.md`, вывод `extract-website` или prompt library в `.superdesign/design-system.md`.
- Вести `design-with-your-model.md` или рисовать черновик в исходниках продукта.

## Успех

Агент, прочитавший только этот файл, выбирает мало референсов Inspo, не копирует бренд и отдаёт черновик Superdesign (ссылка из CLI) плюс промпт на внедрение, не трогая код продукта.

## Fallback

- Нет Inspo MCP: остановись и назови Inspo MCP. Архив не заменяй веб-поиском, экранами по памяти или InspoAI.
- Нет установленного скилла Superdesign или его preflight не стартует (`npx --yes @superdesign/cli@latest`): остановись и назови Superdesign. Отдельный бинарь `superdesign` не ищи. Черновик в файлах продукта не рисуй.
- CLI есть, сессия не авторизована: дальше идёт установленный скилл Superdesign (его `login`), не локальная подмена канваса.
- `recommend` или выбранный `get_screen` пустые: скажи, что архив не дал экран, и остановись.
